Excluded Shockbolt artwork
--------------------------
Raymond Gaustadnes' 2012 Shockbolt artwork has purpose, fee, and modification
restrictions.  The source origin removes the complete lib/tiles/shockbolt
directory, its build recursion, and graphics-menu entries 5 and 6, before
building or installing anything.  No Shockbolt images or mapping files are
included in the repacked source or installed package.  The original copying
statement's explanation is retained as historical notice, not as a licence
claim covering an installed asset.  All other tiles and graphical frontends,
normal gameplay, curses, and sound remain present.

Build, dependencies, and downstream changes
------------------------------------------
This is a source build, not a repackaged upstream executable.  The codeload
archive has configure.ac and autogen.sh but no generated configure.  Its
bootstrap runs aclocal, autoheader, and autoconf.  The production build uses
private paths, curses, X11, SDL2, SDL2_image, SDL2_ttf, and SDL2_mixer; the
ordinary spoiler frontend remains enabled.  Guix supplies the libraries as
separately source-built packages with their own licences and notices; the
historical SDL paragraph in copying.rst does not imply bundled SDL binaries.
The launcher uses Guix Bash and Coreutils under their respective GPL licences.

Downstream changes dated 2026-10-18: remove Shockbolt at source-origin time;
stamp the fixed version via upstream's version-file fallback; install the
immutable data closure in share/faangband; and provide an XDG_DATA_HOME
launcher.  Fix src/main.c's -d parser to split at the first '=' only, retaining
the entire directory path when HOME, XDG_DATA_HOME, or an explicit directory
contains '='.  Missing path values retain the usage error.  Default writable
user, save, scores, archive, info, and bone paths are in XDG_DATA_HOME/faangband
(HOME/.local/share fallback).  Explicit user options, including directory
overrides and -- frontend options, retain their upstream meaning.  No
ANGBAND_PATH support is assumed: the source comment mentions it, but the
pinned implementation reads compiled defaults instead.

Build checks compile a separate upstream --with-no-install --enable-test
configuration with no graphical or sound frontend, using the same source and
a symlink to the original immutable assets (not a second asset copy).  They
run the upstream C unit suites through make -C src tests / the Perl harness,
and the upstream scripted game tests through run-tests, with a private HOME
and an explicit test-only PRIVATE_USER_PATH.  Upstream tilde expansion uses
the passwd database rather than HOME; the test-only compiler definition uses
config.h's existing override guard to contain direct unit-test path setup.
The ordinary launcher needs no tilde patch: initial default path construction
allocates strings only, and all mutable paths are overridden before creation.
SDL extension include paths are supplied explicitly because sdl2-config only
provides the include directory for SDL itself, not its separate extensions.
The unit-test harness output is checked for a nonempty, all-passed total
because this pinned harness does not reliably fail its exit status on an
assertion-count mismatch.  No test cases or assertions are disabled or changed.
These scripted tests are build checks, not evidence of native curses, X11,
SDL2, or audio acceptance.  Native UI acceptance is a separate consumer test.
