Python binding, renderer and font
--------------------------------

The game's original libtcodpy.py is byte-identical to the official libtcod
1.5.1 binding in commit a7cabfda0b0c770d4092f0dec02efbd2a3b6d990 before
packaging integration.  Its original SHA256 is:
9000860b65ec9850b0a20a3025a181719ea5104c4a7bb91cbbbb0385e9a921f4
It retains its complete BSD-3 notice, Copyright (c) 2008,2009,2010 Jice &
Mingos, including all conditions and the disclaimer.  LIBTCOD-LICENSE.txt
retains the complete accompanying library BSD-3 notice.

The shared renderer is the channel's unchanged private dwarftown-libtcod
1.5.1 package, built from the same official commit with Guix dependencies;
no bundled executable or library is used.  Its existing portability work
is reused rather than duplicated.  Its source origin is also a native
build input for this package: the original root cprotos.py and
data/fonts/README.txt are copied from that sanitized, pinned source.

Renderer source archive:
https://codeload.github.com/libtcod/libtcod/tar.gz/a7cabfda0b0c770d4092f0dec02efbd2a3b6d990
Raw archive SHA256:
90f2ade3e2651ae5f0fedeb6b9bae0ad57acfbf6e515a8b1dc85dc8663820827

Only the native integration is changed in the game/binding:
- Load libtcod.so from its absolute immutable store path.
- Enable the original official cprotos.setup_protos on Linux as well as
  macOS.  This supplies pointer-width-correct ctypes return types and the
  upstream argument declarations, rather than a handwritten ABI table.
  The 1.5.1 Key layout is not the older 1.5.0 bitfield layout.
- Read the unchanged original font at its absolute immutable store path.
- Normalize CRLF in the two files receiving substitutions.

These declarations address a static ctypes pointer-width risk, not a
claimed reproduced game crash.  The bounded original-binding and
prototype-enabled map/FOV/image probes both passed during pre-packaging
research; they are not a full game test or proof of gameplay acceptance.

The original font terminal16x16_gs_ro.png is 8240 bytes, SHA256:
0475c1cc68cf710cde725d532acf949f3143d130b90709903571f0f123d68896
It is byte-identical to data/fonts/terminal16x16_gs_ro.png in that libtcod
source.  The directory-scoped original data/fonts/README.txt explicitly
states "These fonts are in public domain."  That real notice is installed
as libtcod-fonts-README.txt; this font finding is independent of the
tutorial-code license discussion above.

The renderer's LIBTCOD-CREDITS.txt, LIBTCOD-LICENSE.txt and README-SDL.txt
are retained (the latter two under renderer-prefixed names alongside the
game's original copies).  Its embedded LodePNG codec's complete noticed
sources are retained as lodepng.c and lodepng.h; the codec has zlib-style
terms.  The renderer links separately packaged Guix SDL, zlib and OpenGL
libraries, not the historical bundled binaries.  README-SDL.txt describes
the historical SDL library and its LGPL terms; the actual replacement
SDL implementation and dependencies carry their own package notices and
licenses.  These component notices do not relicense the GPL game.

Writable data and runtime
-------------------------

The launcher executes the original file using Python 2 with -B -s -E:
no bytecode writes, user-site packages or Python environment overrides.
It does not import the game as a replacement entry point.  This preserves
the original shelve/pickle __main__ class identities.

Immutable game modules and font reside in share/handhrl.  The launcher
uses XDG_DATA_HOME/handhrl, falling back to HOME/.local/share/handhrl, for
the original CWD-relative savegame and scorefile shelve databases.  It sets
umask 077 and rejects relative data roots and both literal and canonically
resolved /gnu/store paths before creating the directory.  Its coreutils
and Python executables use absolute store paths.  No game tree is copied
into HOME and no saved state or deterministic seed is supplied.

No upstream automated test suite was found.  This notice is not a claim
of a package build, reproducibility check, lint pass or native gameplay
acceptance; those are separate consumer-verification results.
