Native package and installation boundary
=========================================

The package is the native console and SDL2/OpenGL local-tiles game with
sound support, original maps, tiles, translations, scripts, settings and
Gooncrawl documents. Native sprint, tutorial, hints, arena and wizard
capabilities are not intentionally replaced by a reduced terminal-only
variant. Separate webserver deployment infrastructure is not a native
playability prerequisite and is not claimed built or deployed here.

The selected upstream Makefile installs dat/des, dat/dlua (plus generated
loadmaps.lua), dat/clua, dat/database, dat/defaults, dat/descript and its
language directories, settings, docs/*.txt, developer/level documents,
docs/license/*.txt and CREDITS.txt; local tiles also installs dat/tiles/*.png.
Anchors: crawl-ref/source/Makefile:1362-1415 at the pinned commit.
The generated tile sheets use rltiles manifests, not every source PNG:
rltiles/Makefile:67 selects main,dngn,floor,wall,feat,player,gui,icons;
source/Makefile:1044,1630 builds/compresses their output. Fixed original
native PNGs include 28 titles/logos/icons. Source/rltiles/UNUSED is not a
blanket native installation list and is not deleted to simplify licensing.

No shipped wav/ogg/mp3/flac/mid/midi pack was found in the stable source.
Sound is the original user-selected-file facility: source/sound.cc:28-37
maps message regexes to user files, :97-110 calls Mix_LoadWAV. SOUND=y with
SDL2_mixer is not a promise of a missing original audio-media package.

util/dcss.svg is a separately scoped CC-BY-3.0 work by Mel Collins, dated
2010-08-15 (embedded metadata:1797-1816), not a CC0 desktop addition. It is
not added to the native installation, nor is a new desktop/SVG integration
claimed. Its source notice remains in the source. Windows/Android/Mac
support files and separate webserver contributions retain source notices
but are not asserted to be native Linux runtime assets or linked code.

Stable notice installation contract (package build, not a deployment receipt):
share/doc/gooncrawl/ contains these five files unchanged:
  gooncrawl-provenance.txt
  gooncrawl-font-notices.txt
  gooncrawl-third-party-notices.txt
  gooncrawl-GPL-3.txt
  gooncrawl-Apache-2.0.txt
The font notice is also copied as
share/gooncrawl/dat/tiles/FONT-LICENSES.txt alongside the exact fonts.
Explicitly retain upstream crawl-ref/licence.txt, CREDITS.txt, all original
docs/license/*.txt and Gooncrawl documents. Unix install-data does not copy
root licence.txt itself; ZIP/mac documentation rules do not close that gap.

gooncrawl-build.patch adds the explicit <ostream> include required by
domino.h's std::ostream declarations, uses the selected gcc executable
instead of the absent cc alias for Makefile HOST identification, and
replaces version.cc's wall-clock __DATE__/__TIME__ string with a fixed
reproducible-build description. The release source pin remains unchanged.

gooncrawl-jester-equipment.patch repairs two actual Jester starting-item
specifications in source/job-data.h:343-344, exposed by Main's real
diagnostic job-data failure. The missing comma between adjacent C++ string
literals combined "quarterstaff ego:chaos" and "robe" into an invalid
"chaosrobe" specification; restoring the comma supplies the two intended
items. The pie specification's stale "ego:blinding" spelling becomes
"ego:atropa", the parser's name for the same SPMSL_BLINDING brand. The
quantity remains four pies; the item brand is not rebalanced or removed.

Source anchors at the original pin: mapdef.cc:4901-4931 missile_brands,
item-prop-enum.h:513-514 and item-name.cc:402-403 establish the atropa
mapping; makeitem.cc:526-527,589-593 intentionally retains SPMSL_BLINDING
for pies. jobs.cc:105-119 give_job_equipment uses the same item_list parser
as :145-162 debug_jobdata, so the malformed definitions affect native
gameplay, not just a diagnostic. The patch is applied to diagnostic,
console and tiles source trees; no test, parser rule, other equipment,
asset or feature is removed to avoid the failure. This records the
bounded source correction, not a post-patch diagnostic/build/play pass.

gooncrawl-stress-pledge.patch changes only the default command in the
upstream test/stress/run harness, adding the public early option
"-extra-opt-first pledge=none". Main's diagnostic run had reached the
normal-game fireworks scenario, which timed out in choose_game/read/wgetch
at HP 0 and turn 0 before the Lua bot could begin gameplay. Gooncrawl's
normal character creation requires a pledge selection (newgame.cc:649-668),
but initfile.cc:290 defaults pledge to "unknown", opening that interactive
menu. The inherited stress configurations do not answer it; their bots
start only after character creation. Earlier sprint scenarios bypass it
by assigning PLEDGE_NONE (newgame.cc:670-673).

The harness's "none" value maps to the existing PLEDGE_NONE
(pledge.cc:37-40). extra-opt-first is applied before scenario rc files
(initfile.cc:1590-1600), so explicit scenario choices retain precedence.
All upstream scenarios, seed 1, assertions, 595-second timeout and exit
handling remain unchanged. This is an unattended-test setup correction,
not production launcher/user-configuration/consumer option injection or
removal of the interactive native pledge feature. No post-patch stress
or whole-build pass is claimed by this provenance amendment.

gooncrawl-stress-lua-loader.patch replaces four stale global require calls
with Crawl's supported crawl_require loader in test/stress/fireworks.rc:27,40,
woken_rest.rc:21 and unwoken_rest.rc:20. CLua::init_lua deliberately excludes
Lua's package library (clua.cc:735-763), so global require is unavailable;
clua.cc:826 registers crawl_require, whose execution failures propagate
at :1232-1250. Production Dungeon Lua already uses this interface in
dat/dlua/dungeon.lua:6-8 and dat/dlua/debug.lua:6.

Main's later diagnostic run exposed nil require/stress errors before the
fireworks timeout. The first two stress scenarios' earlier successful
exits were NOT meaningful setup passes: their entomb/awaken helper calls
had not executed. The patch restores those original helper/setup calls
at all four loader sites without changing the helper code or opening
unrestricted Lua libraries. It does not suppress errors, skip scenarios,
alter assertions or timeouts, or inject production/consumer hooks. The
loader correction's runtime resolution and a complete stress/build pass
remain unverified by this provenance amendment.

Limits and verification boundary
=================================

This is pinned-source/embedded-metadata provenance, not legal advice or a
claim of individual signed author grants for every legacy tile. Positive
integrated GPL permission is supported above; the separate individual-CC0
status of some older art remains unresolved. Short literary quotations in
game databases likewise have no separately recovered author grants (e.g.
source/dat/database/monspeak.txt:5779-5780 comments "Copyright U2?" above one
short phrase). No positive nonfree/NC/ND restriction was identified by the
bounded source audit. Those residuals are disclosed, not silently renamed
CC0, expanded into fabricated restrictions, or removed from the real game.

The source and rights audits retrieved pinned primary material and compared
original archive/font identities. They did not run tilegen or prove a final
installed manifest, build, native play, complete selected system dependency
closure, or deployment. This file does not claim those checks ran. Actual
build/test/installation and corresponding-source receipts belong to the
main integration record. Source URLs, revisions, hashes and original
notices must accompany redistribution; this file alone is not the complete
corresponding source or a substitute for its license obligations.
